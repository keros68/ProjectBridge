# ProjectBridge 产品与技术设计

> 历史设计基线，保留早期决策。当前行为以 [README](../README.md) 和源码为准。

> 状态：首发版设计基线  
> 平台：Windows 10/11  
> 更新：2026-09-15

## 1. 产品定位

ProjectBridge 是一款面向普通用户的本地启动器。用户选择一个项目并点击连接后，ChatGPT 网页端与本机 Codex 可以围绕该项目双向协作；点击断开后，网页端立即失去该项目的访问与任务能力。

它整合 Transceiver 与 codex-with-chatgpt（下文简称 C2C）的能力，但不把两个仓库的源码直接混成一个工程：

- Transceiver 提供网页端向 Codex 委派任务、继续任务、查询状态和传递结果的任务模型。
- C2C 提供只读项目工具、工作区隔离、OAuth 配对、连接诊断和 Codex 请求 ChatGPT 规划或审查的协作模型。
- Local Project Bridge 提供统一界面、项目授权、能力开关、生命周期管理、故障恢复和新手向导。

对用户的承诺只有一句：

> 选择项目，确认能力，点击连接；网页端和 Codex 只在本次授权范围内协作。

## 2. 设计目标

### 2.1 必须做到

1. **双向协作**：网页端可以调用本地 Codex；Codex 可以向指定的 ChatGPT 对话请求规划、复核或补充意见。
2. **一个当前项目**：同一时间只允许一个项目处于连接状态。
3. **一个网页连接**：正式首发版只要求用户在 ChatGPT 中添加一个连接，不让用户理解两个后端和两条隧道。
4. **默认只读**：首次使用即可审查项目，但不能修改文件、执行任意命令或访问项目外路径。
5. **明确授权**：项目与能力均由用户主动选择；切换项目、断开、退出或授权到期后立即撤销。
6. **连接稳定**：运行时路径变化、子进程退出、端口占用和临时地址变化均由启动器发现并处理。
7. **新手友好**：首次设置采用逐步向导，日常使用只需要“选择项目”和“连接”两个主要动作。
8. **运行轻便**：未连接时只保留托盘程序；桥接、隧道和后端按需启动，断开后全部停止。

### 2.2 首发版不做

- 不同时连接多个项目。
- 不提供常驻写入权限。
- 不向网页端暴露通用终端、任意命令或通用 `write_file`。
- 不自研公网隧道、账号系统或 AI 编码代理。
- 不原生解析 PDF、Word、Excel 等复杂格式；首发版以文本和 Git 内容为主。
- 不依赖用户手工编辑 JSON、环境变量或固定的 Node 安装路径。
- 不把 ChatGPT 网页自动化作为唯一的连接基础；必须保留人工确认与可恢复路径。

## 3. 两个上游项目的取舍

| 来源 | 保留 | 不沿用 | 在本产品中的落点 |
| --- | --- | --- | --- |
| Transceiver | 任务创建、继续、状态、停止；请求 ID；来源标记；项目白名单 | 手工启动 bridge 与 tunnel-client；固定运行时路径；用户直接维护配置 | `CodexTaskAdapter`，负责网页端到 Codex 的任务委派 |
| C2C | 单工作区边界；只读读取、搜索和 Git 工具；敏感文件规则；OAuth 配对；Doctor 恢复；规划—执行—审查协议 | 冗长的命令行前置；让用户理解端口、进程和连接器；以浏览器页面状态作为唯一真相 | `ProjectReaderAdapter` 与 `ConversationRelayAdapter` |
| Local Project Bridge | 项目选择、能力开关、进程监管、运行时发现、脱敏日志 | 重做上游已经解决的问题 | 用户唯一接触的桌面入口与统一网关 |

整合原则是“统一产品，不直接拼接源码”。两个上游作为可替换的内部适配器运行，用户不需要分别安装、启动或维护它们。

## 4. 用户看到的产品模型

### 4.1 主窗口

主窗口只保留四个区域：

1. **当前项目**：项目名称与路径，支持添加、移除和切换。
2. **允许的能力**：按项目保存，连接前可调整。
3. **连接状态**：未连接、正在连接、已连接、需要处理。
4. **主要操作**：连接、断开；诊断和高级设置放入次级入口。

建议能力开关如下：

| 开关 | 默认值 | 含义 |
| --- | --- | --- |
| 网页读取项目 | 开启 | 允许网页端读取、搜索和比较当前项目中的安全文本内容 |
| 网页委派 Codex | 关闭 | 允许网页端启动只读、禁网的 Codex 任务，并读取任务结果 |
| Codex 请求网页协作 | 开启 | 允许 Codex 向已绑定的 ChatGPT 对话发送规划或复核请求 |
| 本次允许写入 | 不可用 | 首发版不开放；后续必须使用限时授权 |

“高级”只表示能力影响更大，不应出现端口、MCP、OAuth、Node 路径等内部术语。

### 4.2 首次设置

首次设置控制在三个页面：

1. **选择项目**：选择文件夹并确认显示名称。
2. **自动准备**：检查或准备运行组件，结果以“已就绪 / 需要处理”显示。
3. **连接 ChatGPT**：启动器打开正确的网页设置页，用户只需开启开发人员模式、添加一次连接并确认授权。

平台要求的网页登录和授权确认无法被安全跳过。启动器可以减少输入、复制名称和地址、检测结果并提供深链接，但不能代替用户同意账号权限。

### 4.3 日常使用

```text
打开启动器
  → 选择项目
  → 确认能力
  → 点击“连接”
  → 状态显示“已连接”
  → 在 ChatGPT 或 Codex 中开始协作
  → 点击“断开”
```

登录自启只启动托盘程序，不自动恢复上次项目连接。

## 5. 目标架构

```text
                         ChatGPT Web
                              │
                   一个项目连接 / OAuth
                              │
                         公网安全隧道
                              │
                    Unified MCP Gateway
                              │
                       Session Controller
              ┌───────────────┼───────────────┐
              │               │               │
        Project Policy  Process Supervisor  Diagnostics
              │               │               │
        ┌─────┴─────┐   ┌─────┴─────┐         │
        │           │   │           │         │
 ProjectReader  CodexTask     Conversation     │
   Adapter       Adapter       Relay Adapter   │
   (C2C)      (Transceiver)   (C2C/Transceiver)
        └────────── 当前项目沙箱 ──────────────┘
                              │
                         Local Codex
```

### 5.1 为什么只保留一个网页连接

两个连接器、两个地址和两次授权会把内部实现暴露给用户，也会增加故障点。正式首发版由统一网关向 ChatGPT 暴露一组稳定工具，再在本机转发给两个适配器。

统一网关只负责：

- OAuth 与会话验证；
- 当前项目和能力检查；
- 工具名称与请求 ID 路由；
- 统一错误格式；
- 调用审计和脱敏。

它不负责重新实现文件搜索、Codex 任务生命周期或公网隧道。

### 5.2 过渡实现

当前仓库已经能分别启动 C2C 与 Transceiver，这是技术验证基线。开发期间可以保留两个内部入口用于排错，但公开版本必须完成统一网关，网页端只展示一个 Local Project Bridge 连接。

如果统一网关尚未完成，不应把“双连接版”标记为新手稳定版；最多作为预览版交付。

## 6. 核心模块

### 6.1 Desktop Shell

- WPF 主窗口、托盘菜单、项目管理和首次设置向导。
- 界面只显示用户动作与可执行的解决办法。
- 关闭窗口时进入托盘；选择“退出”才停止程序及所有子进程。

### 6.2 Project Registry

- 保存用户登记的项目、显示名称、能力偏好和最近状态。
- 项目路径保存为规范化绝对路径，比较时忽略 Windows 大小写差异。
- 不保存 API Key、Token、配对码、文件正文和 ChatGPT 消息正文。
- 同一路径只允许登记一次。

### 6.3 Project Policy

每次连接生成不可变的会话策略：

```text
session_id
project_id
canonical_project_path
enabled_capabilities
created_at
expires_at
```

连接期间界面若要切换项目，必须先完整断开旧会话。所有适配器只读取该会话策略，不能各自使用不同项目。

路径校验必须防止 `..`、符号链接、目录联接和重解析点逃逸。敏感文件拒绝规则至少覆盖：

- `.env` 及常见变体；
- 私钥、证书私钥和 SSH 凭据；
- 云服务凭据目录；
- Git 凭据与系统密钥存储；
- 用户通过 `.c2cignore` 或产品忽略文件补充的路径。

### 6.4 Session Controller

连接和断开均由单一控制器执行，不能由界面分别启动两个后端。

连接顺序：

1. 锁定当前项目和能力快照。
2. 检查运行组件与账号能力。
3. 启动统一网关和需要的适配器。
4. 启动隧道并完成 MCP 初始化探测。
5. 核对网页端看到的工作区名称与项目 ID。
6. 全部成功后才进入“已连接”。

任一步失败都按相反顺序回滚，不能留下半连接状态。

断开顺序：

1. 停止接受新请求。
2. 取消或冻结进行中的任务并保存最小状态。
3. 撤销当前 OAuth 会话或配对令牌。
4. 停止隧道、网关和后端子进程。
5. 确认本地监听端口已关闭。
6. 清理临时会话配置和写入租约。

### 6.5 Runtime Discovery

运行时按以下顺序发现：

1. 发布包内固定版本；
2. 应用管理目录中的已验证版本；
3. 当前 PATH；
4. 官方常见安装目录。

不得记录 WinGet 的版本化绝对路径。发现 Node、Codex、cloudflared 或 tunnel-client 后必须执行轻量探测，而不是只判断文件存在。

### 6.6 Process Supervisor

- 所有子进程由启动器创建、记录 PID，并放入同一 Windows Job Object；启动器异常退出时由系统回收。
- 每个组件均有启动超时、健康检查和退出原因。
- 自动恢复使用退避策略，连续失败三次后停止重试并显示具体操作。
- 隧道失效时先判断账号登录、地址变化和网络故障，不能一律提示“重装 Node”。
- 端口由系统动态分配；仅兼容旧后端时才保留固定端口，并在启动前验证占用者。

### 6.7 Adapters

适配器只做协议转换，不保存第二份项目权限。

- `ProjectReaderAdapter`：工作区信息、目录、读取、搜索、Git 状态与差异。
- `CodexTaskAdapter`：任务开始、继续、状态、停止和结果读取。
- `ConversationRelayAdapter`：把 Codex 的规划、阻塞和复核请求发送到绑定对话，并按 `request_id` 导回回复。

每个跨端消息都携带：

```text
request_id
project_id
session_id
source
task_id（如适用）
iteration（如适用）
```

来源标记由系统生成，不能依赖模型自行填写。

## 7. 双向协作协议

### 7.1 网页端到 Codex

```text
ChatGPT 发起任务
  → 网关校验项目与“网页委派 Codex”开关
  → 创建只读、禁网的 Codex 任务
  → 返回 task_id
  → 网页端轮询或等待状态
  → 读取结构化结果
```

首发版任务只能读取当前项目。即使用户误开更高权限的本机 Codex 配置，启动器仍应在任务层再次固定只读和禁网。

### 7.2 Codex 到网页端

```text
Codex 提交咨询请求
  → Relay 绑定当前 project_id 与 request_id
  → ChatGPT 返回规划、复核或补充意见
  → Relay 将回复交还原任务
  → Codex 保留执行权并决定是否采纳
```

ChatGPT 是规划与复核层，Codex 是本地执行层。网页回复不能绕过本地策略直接修改文件。

### 7.3 能力不足时的降级

启动器应检测当前 ChatGPT 账号实际支持的工具能力，不把账号套餐写死在程序中。

- 支持完整工具时：显示双向协作能力。
- 只支持读取时：保留项目审查与 Codex 请求网页协作，禁用网页委派任务，并说明原因。
- 无法使用自定义连接时：停止设置并给出官方设置入口，不伪装为已经连接。

## 8. 权限与写入设计

### 8.1 首发版

- 默认且强制只读。
- 网页端不获得通用 shell。
- Codex 委派任务固定为只读、禁网。
- 项目外路径统一拒绝。

### 8.2 后续限时写入

写入不能通过永久配置或 bridge 进程级环境变量开启，必须使用本地能力租约：

```text
lease_id
project_id
session_id
permissions: [write]
issued_at
expires_at
```

开启流程：用户在启动器中选择“本次允许写入”→ 明确看到项目路径和有效期 → 本机确认 → 生成租约。租约在超时、断开、切换项目、退出、注销或重启时自动失效。

即使开放写入，也只允许通过 Codex 的受控任务沙箱执行，不新增通用文件写入工具。

## 9. 稳定性与恢复

### 9.1 状态机

```text
未连接
  → 正在检查
  → 正在启动
  → 正在授权（仅首次或失效时）
  → 已连接
  → 正在恢复
  → 需要处理
  → 正在断开
  → 未连接
```

状态必须由会话控制器的真实探测结果驱动，不能只依据进程是否存在。

### 9.2 错误信息

每个错误只显示三项：

- 发生了什么；
- 哪项能力受影响；
- 用户现在可以做什么。

诊断详情可复制，但必须隐藏 Token、API Key、OAuth 代码、配对码、URL 查询参数和文件正文。

### 9.3 常见恢复

| 情况 | 自动处理 | 需要用户 |
| --- | --- | --- |
| Node 或 Codex 路径失效 | 重新发现并探测 | 组件确实不存在时安装 |
| bridge 意外退出 | 退避重启，最多三次 | 查看最终原因 |
| tunnel 进程退出 | 判断登录与网络后重启 | 登录或账号确认 |
| 临时公网地址变化 | 生成新地址并打开正确设置页 | 在 ChatGPT 确认更新 |
| OAuth 过期或撤销 | 生成新的授权流程 | 在网页确认 |
| 项目被移动 | 阻止连接 | 重新选择目录 |
| 端口冲突 | 改用可用端口 | 通常无需处理 |

## 10. 轻量化指标

“轻量”优先指不常驻重型后端，而不是单纯追求最小压缩包。

首发目标：

- 未连接：仅托盘程序，平均 CPU 接近 0，内存目标不超过 120 MB。
- 已连接但无任务：除隧道与网关外不启动 Codex；平均 CPU 目标低于 1%。
- 断开后：30 秒内停止全部桥接、隧道和任务子进程。
- 后台健康检查：空闲时不高于每 5 秒一次，失败时使用退避。
- 新手完整包：携带固定版本运行组件，以安装后无需寻找 Node 为优先；下载体积单独记录并持续压缩。

可同时提供“完整包”和面向开发者的“精简包”，但帮助文档默认只推荐完整包，避免新用户选错。

## 11. 安装、更新与数据目录

### 11.1 发布形式

首发提供一个签名安装程序；免安装压缩包作为备用。用户不需要分别下载 Transceiver、C2C、cloudflared 或 tunnel-client。

完整包固定并记录所有上游版本。自动更新首发可只做“检查并提示”，不在连接中静默替换后端。

### 11.2 本地目录

建议结构：

```text
%LOCALAPPDATA%\LocalProjectBridge\
  projects.json          # 项目登记与偏好
  runtime\               # 受管理的固定运行组件
  backends\              # 独立上游后端
  sessions\<session_id>\ # 临时会话配置
  logs\                  # 脱敏日志
```

退出或断开时删除会话目录；项目登记和必要的连接元数据保留。凭据交由系统或上游安全存储处理，不写入 `projects.json`。

## 12. 许可与上游边界

- Transceiver 使用 AGPL-3.0，首发继续作为独立进程或独立适配器分发，保留源码、许可证和修改说明。
- C2C 使用 MIT，可按许可证复用，但仍优先通过稳定命令与协议适配，减少维护分叉。
- Local Project Bridge 自有代码单独授权，发布前需明确许可证。
- `THIRD-PARTY-NOTICES.md` 与发布包必须记录确切版本和来源。

如果未来把 Transceiver 代码直接链接或复制进统一网关，必须先重新评估整个发行物的 AGPL 义务。这里是工程边界，不代替正式法律意见。

## 13. 当前实现与目标差距

### 13.1 当前仓库已具备（2026-09-15 更新）

- 分层架构：`src/LocalProjectBridge.Core`（会话、安全、进程、适配器、网关，无 UI 依赖）+ `src/LocalProjectBridge`（WPF 壳）+ `src/CodexShim` + `tests/LocalProjectBridge.Core.Tests`（xunit）。
- WPF 主窗口、托盘和登录自启；项目登记与单项目选择。
- 统一 Session Controller：9.1 完整状态机、连接原子性与失败回滚、断开顺序、会话目录按 `sessions\<session_id>` 隔离并在断开/退出/启动时清理。
- 不可变 SessionPolicy 与按项目保存的能力开关；开关写入 Transceiver 会话配置成为后端强制策略（`allowCodexTasks`/`sync`、`unknownProject: deny`）。
- ProjectPathGuard：`GetFinalPathNameByHandle` 最终路径解析；拒绝 `..`、绝对路径与联接/符号链接逃逸；中文与 OneDrive 路径可用。
- SensitiveFilePolicy：`.env` 变体、私钥/证书扩展名、云凭据目录、`.git`、Git 凭据与系统密钥存储，以及 `.c2cignore` / `.bridgeignore` 自定义规则。
- Windows Job Object（KILL_ON_JOB_CLOSE）回收 Transceiver 子进程树；端口由系统动态分配。
- Transceiver 与 C2C 两个适配器实现统一 `IConnectableAdapter` 契约；C2C 连接后完成 doctor 与工作区身份核对。
- 统一网关基础（阶段 B 起点）：MCP JSON-RPC 分发器（initialize/tools/list/tools/call、统一错误格式）、策略强制的只读工具面（project_info、list_directory、read_text_file、search_files、git_status、git_diff）、Codex 任务代理与来源标记注入、127.0.0.1 动态端口本地监听；在设置中以“统一网关（试验性）”开启。
- Node、Codex、bridge、隧道的动态发现（CodexShim 与启动器共享发现结果）；脱敏日志；错误三要素分类（发生了什么/影响哪项能力/下一步做什么）。
- 首次设置向导与免安装发布脚本；108 个单元测试覆盖路径逃逸、敏感文件、会话策略与并发保存、控制器超时与回滚、Job Object 进程回收、能力映射、C2C 机器输出、动态隧道目标与网关协议。

### 13.2 达到正式首发前仍需完成

1. 把 C2C 的 Codex→网页协作入口并入统一网关；当前 Transceiver 已由网关统一接管动态隧道目标，但完整双向协作仍需要 C2C 的独立连接。
2. 首次向导覆盖双向协作：委派与 Codex 请求网页协作的账号准备步骤。
3. 账号能力检测（不把套餐写死）与临时地址变化后的自动恢复流程。
4. 会话级限时写入租约（阶段 D）。
5. 签名安装包与包内受管理运行时，取消对外部 Node 的要求。
6. 双向端到端验证、故障注入与性能验收（需要真实上游与 ChatGPT 环境）。

## 14. 开发阶段

### 阶段 A：收拢现有原型

- 建立单一 Session Controller 与原子连接/回滚。
- 固化项目策略、能力开关和统一状态机。
- 处理中文路径、OneDrive 路径、路径移动和进程残留。
- 完成现有双入口的端到端技术验证。

完成条件：两个方向都能在同一项目上完成真实请求，断开后无残留访问。

### 阶段 B：形成新手首发版

- 增加 Unified MCP Gateway。
- 合并为一个网页连接和一次 OAuth 设置。
- 完成三步向导、账号能力检测、自动修复与诊断文案。
- 发布携带固定运行组件的签名安装包。

完成条件：新用户不阅读 README，也能在向导内完成首次连接；第二次使用只需选择项目并点击连接。

### 阶段 C：稳定性与安全验收

- 故障注入：杀死 bridge、隧道、Codex 和启动器。
- 安全验证：项目切换、路径逃逸、敏感文件、权限关闭和令牌撤销。
- 性能验证：空闲 CPU、内存、连接耗时和断开清理。
- 上游兼容：固定版本、协议探测和升级回滚。

完成条件：全部首发验收场景通过，且失败时给出可执行的恢复动作。

### 阶段 D：限时写入

- 增加项目级、会话级、限时能力租约。
- 只通过受控 Codex 任务开放写入。
- 增加本地确认、到期撤销和审计摘要。

写入不是首发阻塞项，不能为赶进度退回永久写权限。

## 15. 首发验收清单

### 功能

- [ ] 干净 Windows 环境只下载一个安装包即可启动。
- [ ] 首次向导只要求一次 ChatGPT 连接设置。
- [ ] 可登记多个项目，但同一时间只连接一个。
- [ ] 网页端可读取当前项目的安全文本、搜索结果与 Git 差异。
- [ ] 开启委派后，网页端可启动只读 Codex 任务并取得真实结果。
- [ ] Codex 可向绑定的 ChatGPT 对话请求复核，并收到匹配 `request_id` 的回复。
- [ ] 关闭某项能力后，对应工具立即不可用。
- [ ] 切换项目必须先断开旧项目，旧项目不能继续读取或执行任务。

### 安全

- [ ] `..`、符号链接、目录联接和重解析点不能访问项目外内容。
- [ ] `.env`、私钥、凭据和用户忽略文件不能通过读取或搜索泄露。
- [ ] 首发版网页端无法写文件、运行通用命令或启用网络。
- [ ] 断开、退出和会话过期都会撤销令牌并清理会话配置。
- [ ] 日志与诊断包不包含 Token、Key、配对码和文件正文。

### 稳定性

- [ ] Node 或 Codex 更新路径后可重新发现，不引用失效的 WinGet 版本目录。
- [ ] bridge 或 tunnel 单次崩溃可以恢复；连续失败会停止重试并说明原因。
- [ ] 临时地址变化有明确恢复流程，不要求用户重装程序。
- [ ] 断开后子进程退出，本地监听关闭。
- [ ] 登录自启后保持未连接。

### 体验与性能

- [ ] 首次设置始终显示当前步骤、正在做什么和下一步。
- [ ] 日常连接不要求命令行、复制配置或寻找进程。
- [ ] 空闲资源占用达到第 10 节目标。
- [ ] 错误提示包含可直接执行的下一步。

## 16. 决策摘要

1. 产品核心是稳定的 ChatGPT 网页端与 Codex 双向协作，不是单纯的项目阅读器。
2. 两个上游在能力层整合，在代码和许可层保持独立适配。
3. 正式首发只保留一个网页连接；当前双入口实现属于过渡原型。
4. 同时只连接一个项目，默认只读，写入延后到限时租约完成后。
5. 新手版优先“一个安装包、三步设置、日常一键连接”；内部进程和路径不暴露给用户。
6. 轻量化以空闲时不运行后端为主，完整包体积让位于安装可靠性。
